Case Study · Open-Source Contribution

Shipping the most-requested mode in career-ops on the first PR.

The career-ops project already evaluated job offers and generated tailored CVs, leaving cover letters as the last manual step. I designed and shipped the end-to-end cover letter mode (PR #807): a 10-step conversational workflow, strict CV-grounded metric verification, and a zero-dependency Node.js and Playwright PDF renderer.

01 — The Business Driver

Closing the last manual step in the career-ops application pipeline

career-ops automated job evaluation and CV generation, but users still had to write cover letters from scratch or paste generic LLM drafts.

GAP

No structured path from JD to finished PDF

The repo had no workflow to turn a job description and user profile into a formatted cover letter PDF, leaving issue #199 as the project's top open feature request.

Missing workflow = cover letters stayed manual and disconnected
QUALITY

Preventing invented metrics and keyword stuffing

Unconstrained LLM prompts routinely exaggerate numbers or fabricate experience. Any claim not backed by the candidate's actual CV creates an immediate liability in interviews.

Invented claims = broken credibility during technical screens
CONTROL

Mandatory user sign-off before PDF rendering

Users needed to review and approve the exact text in chat before the tool generated a final application PDF.

Explicit approval gate = no unreviewed draft ever becomes a PDF
02 — The Obstacles

Three technical and editorial constraints

Getting the PR merged required strict factual grounding against the user's CV, zero new runtime dependencies, and support for two different entry workflows.

INTEGRITY

LLMs round or extrapolate resume numbers

Left to themselves, language models frequently alter percentages or combine separate project metrics when summarizing CV bullets.

Altered metrics = numbers that don't match the attached CV
ARCHITECTURE

Strict Node.js-only repository standard

An early prototype used a Python script to build the PDF. The maintainer required a single Node.js runtime with zero new package dependencies.

Second runtime = PR rejected on architecture grounds
SCOPE

Supporting both raw JDs and evaluated offers

The mode had to run equally well from a freshly pasted job description or from an existing career-ops evaluation report without duplicating prompt logic.

Shared logic = single code path for both entry points
03 — The Solution

Research, CV-grounded bullet selection, human sign-off, and Playwright rendering

The workflow gathers company context, locks metrics to the source CV, requires explicit user approval in chat, and renders the final A4 PDF through Playwright.

1
10-step conversational flow JD → research → prompts → draft → approval

The mode file walks from JD ingestion through company web search, competency extraction, four clarifying questions for the candidate, and a mandatory approval gate before calling the PDF renderer.modes/cover.md · Claude Code

2
Achievement selection from cv.md score → select → preserve

Every bullet in cv.md is scored against the role's primary competencies. The top 4 to 5 bullets are selected and their exact figures are locked so surrounding prose can adapt terminology without altering any metric.Achievement scoring · cv.md

3
Zero-dependency Node.js PDF renderer JSON payload → HTML template → A4 PDF

An ESM script takes a validated JSON payload, injects HTML-escaped tokens into an A4 print template, and renders the PDF using the repo's existing Playwright setup with zero added packages.generate-cover-letter.mjs · Playwright

4
10 enforced writing constraints active voice · no buzzwords · 350–420 words

The drafting step enforces ten editorial rules: active voice, a blocklist of corporate clichés (leverage, synergy, spearheaded, north star), no generic openings, every claim tied to a named system or number, and a 350 to 420 word count.Language rules · 350–420 word target

05 — What the Feature Makes Possible

Fast, CV-verified cover letters matched to the resume layout

⚡

Every letter is company-specific and human-approved before rendering

Because the approval gate requires the user to read and confirm the draft in chat before Playwright runs, no unreviewed text ever gets exported to a PDF.

⊕

Role alignment without altered numbers

Job description terms are split into ATS keywords and domain concepts. The prose adapts around the candidate's accomplishments while keeping every number identical to cv.md.

✕

Zero new dependencies added to the repository

Reusing the existing Node.js and Playwright pipeline kept the repository dependency-free, which the maintainer highlighted when merging PR #807.

↻

Portable across roles and geographies

The renderer reads candidate details and proof points dynamically from cv.md and profile.yml, with zero hardcoded names or regional assumptions.

⤳

Matched typography with the generated CV

Sharing the A4 HTML template and Playwright print settings ensures the cover letter and CV arrive as a visually consistent application packet.
